# 光标上下文与安全门控测试

OpenLess 会在听写开始时尝试读取当前输入位置附近的少量文字，并在本机用于专名纠错。这个过程不会生成或修改词表；词条只能由用户在词表页手动添加。

## 1. 光标上下文探针

打开 **设置 → 高级 → 调试工具 → 光标上下文探针**。

点击“探测（5 秒后）”，切到目标应用并把光标放进正文，再切回 OpenLess 查看结果。

预期结果：

| 场景 | 预期 |
|---|---|
| 备忘录、文本编辑、普通输入框 | `ok`，显示光标附近文字 |
| 浏览器密码框 | `blocked`，原因包含安全文本框 |
| Terminal、iTerm、Warp 等终端 | `blocked`，原因包含敏感应用 |
| 1Password、Passwords 等密码管理器 | `blocked`，原因包含敏感应用 |
| 无法确认焦点元素所属应用 | 拒绝读取，不得猜测或退回全文读取 |

密码框、终端或密码管理器任何一项未被拦住，都应停止测试并修复。

## 2. 听写仍能正常工作

光标内容读取失败、超时或被安全门控拦截时，语音识别和本地润色仍应继续。失败只表示本次没有光标参考，不能阻止录音或上屏。

对一个响应缓慢或无法读取的应用触发听写：

- 单次辅助功能调用应有短超时；
- 整次读取应在规定时限内返回；
- 界面不应冻结；
- 听写应继续使用语音、手动词表和其他可用上下文。

## 3. 上下文不得被复述

在光标前放置一段容易辨认的已有正文，再口述一段较短的新内容。

例如已有正文是：

```text
这个模块的接口设计得不太好，
```

口述：

```text
还得再改
```

输出只能整理本次口述，不能把已有正文再次插入。光标内容只是专名和语境参考，不是需要续写、回答或执行的指令。

## 4. 目标变化时必须拒绝

触发听写后，在识别或润色完成前切换应用、窗口或输入位置。

预期：

- 屏幕文字识别发现前台应用、窗口或焦点归属变化时，放弃本次屏幕上下文；
- 上屏前无法恢复或确认原目标时，不向当前新目标盲目写字；
- 失败时使用现有的复制兜底提示，让用户自行粘贴。

## 5. 屏幕文字识别安全检查

屏幕文字识别只在听写触发时尝试，并且必须满足：

- 用户已经授予屏幕录制权限；
- 当前不是 OpenLess 自己、密码框、密码管理器、终端或安全输入状态；
- 前台应用、窗口和焦点元素仍与触发时一致；
- 只截取已确认的目标窗口，不退回整屏截图；
- 截图只在内存处理，不保存文件；
- 结果未在润色输入冻结前完成时直接忽略，不等待。

## 6. 词表不应自动变化

测试前记录词表中的词条数量和内容。完成以下操作后再次检查：

1. 正常听写并上屏；
2. 手动修改刚插入的文字；
3. 使用光标上下文；
4. 使用屏幕文字识别；
5. 查看或重新润色历史记录。

预期：词条数量、词条内容和启用状态都不变。已有词条的使用次数可以增加。只有在词表页明确添加、启用、禁用或删除时，词表内容才改变。

## 7. 日志和历史边界

普通日志只应记录状态、耗时、字数和拒绝原因，不应记录光标正文、屏幕文字或截图。

用户授权保存的完整润色诊断可能包含实际提示词，以及其中的光标、屏幕文字和前轮文本。它只保存在本机历史中：

- 删除单条历史会删除该条诊断；
- 同一文字可能已经进入其他记录的提示词副本；
- 清空全部历史才会删除全部历史记录中的副本。
